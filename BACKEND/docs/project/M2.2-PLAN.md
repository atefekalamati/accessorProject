## Taskها
**CAT-05 — Media + storage (HIGH، از MEDIUM ارتقا یافت چون فایل‌های آپلودی را پردازش می‌کند؛ 4h)**
- scope: interface `FileStorage` با پیاده‌سازی‌های `LocalFileStorage` و `InMemoryFileStorage` (ADR-009). `ImageProcessor` با Pillow: تشخیص نوع با magic bytes (jpeg، png، webp)، حجم ≤ 5MB، `MAX_IMAGE_PIXELS`، ابعاد از header، re-encode و حذف EXIF. جدول `media` (`storage_key`، `content_type`، `size_bytes`، `width`، `height`، `created_by`) و `product_media` (product، variant، `alt_text`، `display_order`، `is_main` با partial unique).
- endpoint `POST /admin/media` (multipart) برای فایل‌هایی که به محصول تعلق ندارند. `categories.image_url` با `image_media_id` جایگزین می‌شود (FK به `media`) و `MEDIA_ALLOWED_HOSTS` و `check_image_url` حذف می‌شوند (ADR-025).
- settingهای جدید `MEDIA_STORAGE`، `MEDIA_ROOT` و `MEDIA_PUBLIC_BASE_URL`. production با `memory` شروع نمی‌شود.
- ریسک‌ها: decompression bomb؛ فایل polyglot؛ path traversal در `storage_key` (کلید را سرور می‌سازد: uuid + پسوند)؛ فایل یتیم وقتی DB rollback شود (حذف بعد از rollback و پاک‌سازی بعدی در OPS)؛ از دست رفتن داده `image_url` در migration (فقط دیتابیس dev).

**CAT-09 — CategoryFilter (MEDIUM، 3h)**
- scope: مدل `category_filters` (`attribute_key`، `label`، `filter_type`، `display_order`، `is_active`)، `GET /categories/{slug}/filters` (فقط کلیدها و مقادیری که در محصولات منتشرشده دسته واقعاً وجود دارند، با تعداد)، و `PATCH /admin/categories/{id}/filters` (جایگزینی کل مجموعه، `catalog:manage`، audit).
- ریسک‌ها: N+1 در شمارش مقادیر (یک کوئری GROUP BY)؛ SD rule برای دسته پنهان و محصول حذف‌شده.

**PRC-01 — فیلدهای قیمت و PricingSetting (HIGH، 3h)**
- scope: ستون‌های `base_price`، `sale_price`، `sale_start_at`، `sale_end_at`، `tax_enabled` و `price_version` روی variant، از نوع BIGINT تومان با CHECKهای `sale ≤ base`، مقادیر مثبت و بازه معتبر. ردیف PricingSetting (`tax_enabled=false`، `nearest`/1).
- ریسک‌ها: float یا overflow (BIGINT و CHECK)؛ تنوع فعال بدون قیمت (قاعده 422 در CAT-11).

**CAT-11 — Admin product/variant/media CRUD (HIGH چون قیمت اولیه را ذخیره می‌کند؛ 5h)**
- scope: ۱۲ endpoint بخش «محصولات» ✓؛ گراف وضعیت و `publish_blockers`؛ قفل روی ردیف Product؛ قیمت اولیه فقط با `pricing:update`؛ همه audit actionهای PRD.
- ریسک‌ها: انتشار همزمان با حذف آخرین تنوع یا تصویر اصلی (FOR UPDATE روی Product)؛ دو تصویر اصلی (partial unique + جابه‌جایی در یک تراکنش)؛ نادیده‌گرفتن فیلدهای سیستمی؛ ترکیب گزینه تکراری؛ حذف فایل فقط بعد از commit.

**PRC-02 — تابع خالص قیمت (HIGH، 5h)**: بازه sale، تخفیف، مالیات، حمل و گردکردن یک‌باره (ADR-014)، با unit test جدولی. ریسک: off-by-one در مرز بازه (بازه نیمه‌باز با تست مرزی).

**INV-01 — Warehouse + InventoryItem (HIGH، 3h)**: یک انبار پیش‌فرض و موجودی per variant با CHECKهای نامنفی. بدون رزرو. ریسک: انبار پیش‌فرض تکراری (partial unique).

**INV-03 — free stock و stock status خالص (HIGH، 2h)**: `free = total − active reservations` و سه وضعیت، با تست جدولی. جدول رزرو هنوز وجود ندارد، پس مقدار آن ورودی تابع است.

**CAT-08 — `GET /products/{slug}` (MEDIUM، 3h)**: قرارداد کامل PRD؛ slug نامعتبر → 400؛ پاسخ 404 یکسان برای همه حالت‌های پنهان؛ بدون N+1؛ تست کلیدهای پاسخ. ریسک: نشت فیلد داخلی (schema صریح).

**CAT-07 — لیست عمومی محصولات (MEDIUM، 6h)**: `GET /products` و `GET /categories/{slug}/products`؛ فیلترهای allowlist؛ sortهای `newest`، `price_asc`، `price_desc` و `discount_desc`؛ helper صفحه‌بندی مشترک. ریسک‌ها: کوئری سنگین (سقف limit، index)؛ مرتب‌سازی پایدار با `id`.

**CAT-12 — تست‌های API کاتالوگ (MEDIUM، 3h)**: پوشش 400/401/403/404/409/422 برای همه endpointها و یک تست end-to-end کاتالوگ.
