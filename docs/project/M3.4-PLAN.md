## ORD-01 — Order schema (HIGH، 5h)
- Scope: جدول‌های `orders` (شماره `ORD-YYYY-NNNNNN` از sequence، سه وضعیت مستقل با CHECK، `cancel_reason`، اجزای مبلغ BIGINT با CHECK جمع، موبایل snapshot، کد تخفیف و روش ارسال snapshot)، `order_items` (snapshot عنوان محصول، SKU، برچسب تنوع، قیمت واحد و اجزای خط، ترتیب پایدار)، `order_price_snapshots` (سیاست قیمت، fingerprint، `calculated_at`)، `order_addresses` (کپی آدرس)، `order_status_history`. FK `order_id` در `inventory_reservations` و `discount_redemptions` (RESTRICT). migration `20261018_0022`.
- ریسک‌ها: snapshot ناقص (سفارش قبلی با تغییر محصول عوض شود → تست)؛ عدم سازگاری جمع مبالغ (CHECK DB)؛ شکستن تست‌های موجود با FK جدید (fixture `make_order` و بازنویسی order_idهای تصادفی)؛ شماره سفارش شبیه موبایل (CHECK الگو).

## ORD-02 — Idempotency-Key (HIGH، 3h)
- Scope: جدول `idempotency_keys` (کاربر، scope، key، hash بدنه canonical، پاسخ، `expires_at` = ۲۴ ساعت)؛ سرویس در تراکنش فراخواننده با advisory lock هر (کاربر، scope، key): همان بدنه → پاسخ ذخیره‌شده، بدنه متفاوت → 422 `IDEMPOTENCY_KEY_REUSED`، منقضی → اجرای تازه؛ فقط پاسخ موفق ذخیره می‌شود. header نبود/نامعتبر → 400.
- ریسک‌ها: اجرای دوباره در همزمانی (تست gather → یک اجرا)؛ نشت بین کاربران (کلید per-user؛ تست)؛ canonical hash ناپایدار (unit test ترتیب کلیدها).

## ORD-03 — POST /checkout/validate (HIGH، 3h)
- Scope: سبد کاربر + `address_id` + `shipping_method_id` → quote کامل (خطوط با ترتیب id، کد، ارسال طبق ADR-045، مالیات) و fingerprint که قیمت، کد و مبلغ آن، و روش و هزینه ارسال را می‌پوشاند. SD rule، موجودی آزاد مؤثر، 422 برای کد/ارسال نامعتبر، آدرس دیگران یا ناموجود 404؛ سبد خالی 422.
- ریسک‌ها: fingerprint ناقص (تست تغییر هر جزء)؛ ترتیب خطوط (تست shuffle)؛ آدرس دیگران (404).

## ORD-05 — State machine (HIGH، 4h)
- Scope: جدول انتقال خالص برای order/payment/shipment؛ تابع اعمال انتقال زیر `FOR UPDATE` با ثبت `order_status_history` و audit؛ انتقال نامعتبر → 422 `INVALID_STATE_TRANSITION`. بدون endpoint عمومی (ادمین فاز ۴، لغو مشتری در ORD-04/ORD-06).
- ریسک‌ها: انتقال غیرمجاز (تست جدولی همه جفت‌ها)؛ رقابت دو انتقال (تست همزمانی).

## CAT-17 — best_selling (MEDIUM، 1h)
- Scope: sort `best_selling` در لیست محصولات از OrderItemهای سفارش‌های `paid`؛ allowlist؛ tie با `id`.

## ORD-04 — POST /orders (HIGH، 5h؛ plan جدا برای تأیید)
- Scope: موبایل تأییدشده، Idempotency-Key، fingerprint → 409 `PRICE_CHANGED`، تراکنش واحد با ترتیب lock ADR-044 (سبد → advisory سفارش → inventory → کد → redemption)، رزرو ۱۵ دقیقه، snapshotها، redemption pending؛ سبد خالی نمی‌شود.

## ORD-06 — Order tests (HIGH، 3h)
- Scope: idempotency، PRICE_CHANGED، INSUFFICIENT_STOCK، SD rule، end-to-end سبد → validate → order.
